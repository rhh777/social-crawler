# Agent 分析

Agent 使用 Claude Agent SDK 分析已采集的数据。点击发送才会调用模型，采集完成后不会自动分析。

## 配置模型

在 **系统配置 → Agent 模型配置** 或 **Agent 分析 → 配置模型** 中填写：

| 字段 | 填写内容 |
| --- | --- |
| API Key | 模型服务的密钥；保存后不回显，留空则保留原值 |
| 接口地址 | 模型服务的兼容接口地址 |
| 模型名称 | 服务支持的模型 ID |

“高级运行参数”提供常用的 Claude Agent SDK 控制项：

| 字段 | 作用 |
| --- | --- |
| 备用模型 | 主模型不可用时由 SDK 尝试使用的模型 ID |
| 最大轮次 | 限制一次发送可进行的 Agent 对话/工具轮次；留空不限制 |
| 本轮预算上限 | SDK 估算费用达到指定美元金额时停止；留空不限制 |
| 消息缓冲区 | SDK 读取 CLI 单条 JSON 消息的上限，默认 8 MiB |
| 推理模式 | 使用模型默认、自适应、固定 Token 预算或关闭扩展思考 |
| 思考 Token 预算 | 仅“固定 Token 预算”模式使用 |
| 推理强度 | `low`、`medium`、`high`、`xhigh` 或 `max` |

备用模型、预算、推理模式和推理强度需要模型服务兼容对应能力。第三方或自定义模型的
费用统计可能不准确；缓冲区仅控制本地 SDK 读取上限，模型服务仍可能有自己的请求大小限制。

例如：

```text
接口地址：https://model.example.com/anthropic
模型名称：example-model
```

地址可以带 `/v1`、`/v1/messages` 或 `/v1/chat/completions` 后缀，程序会转换为 SDK 使用的根路径，不会仅根据路径判断服务是否兼容。

保存后，下一次发送使用新配置；正在执行的消息不受影响。保存操作不调用模型。点击“检测可用性”会通过实际执行所用的 SDK 发送一条简短消息，并显示模型回复；该操作可能产生少量模型费用。

配置文件位于运行目录的 `data/web/agent-settings.json`，权限为 `0600`。本地脚本的默认运行目录是 `social-crawler-local/`，Compose 将此文件保存在 `crawler-data` 卷中。

也可以在本机的 `.env.local` 或部署用的 `.env.deploy` 中配置：

```dotenv
ANTHROPIC_API_KEY='你的 API key'
CRAWLER_AGENT_API_URL=https://api.anthropic.com
CRAWLER_AGENT_MODEL=sonnet
```

页面保存值优先于环境变量。`ANTHROPIC_BASE_URL` 可作为接口地址的备用配置；完整读取规则见 [配置指南](configuration.md)。未设置密钥时仍可采集和浏览数据，分析页会提示先配置模型。

## 开始分析

| 入口 | 可以使用的数据 |
| --- | --- |
| 内容库 → 帖子 → 分析这个帖子 | 该帖子及已保存的评论、回复 |
| 采集工作台 → 任务 → 分析本次采集结果 | 创建会话时已经保存的任务结果 |
| Agent 分析 → 新建 | 数据库中的帖子、评论和任务 |

任务分析使用固定快照。任务继续采集后，旧会话不会自动获得新增数据；需要从任务入口重新创建会话。

新建会话时选择执行模式：

| 模式 | 适合场景 | 能力 |
| --- | --- | --- |
| 只读分析 | 内容洞察、评论归纳、任务结果分析 | 仅查询当前范围内的采集数据和已下载媒体，不执行任意命令 |
| 工作区 Agent | 需要处理文件、编写程序或调用本地工具的任务 | 开放 Claude Code 工具、可发现的 Skills 和全部命令权限，在项目根目录自动执行 |

模式会随会话保存，创建后不能切换。工作区 Agent 可能修改或删除项目文件，也可能执行 Skill 中定义的操作，只应在理解任务影响时选择；不需要这些能力时使用默认的只读分析。

输入问题并发送，可以继续追问或点击证据查看原文。点击“停止分析”会保留已收到的输出，已经发出的模型请求仍可能计费。服务重启或分析失败后不会自动重试，需要手动发送下一条消息。高级配置可以设置 SDK 单轮预算上限，但第三方模型的费用识别和停止行为以服务兼容性为准。

## 会话与证据

会话列表显示最近 100 个会话，支持搜索、重命名和导出 Markdown。消息中的查询步骤默认折叠，证据可单独查看。阅读旧消息时，新输出不会把页面拉回底部。

只读分析只能使用业务查询和媒体工具，不能运行 Shell、任意 SQL、读取任意文件或发起采集。查询支持分页，每页最多 100 条。提供给模型的证据会随会话保存，便于核对结论；评论和回复可能未采全，分析时需要结合采集范围看待结果。

## 帖子图片和视频

采集前开启“下载图片和视频到本地存储”，Agent 才能分析帖子媒体。只读分析会先查看媒体清单，再直接读取图片；视频需要运行环境安装 `ffmpeg` 和 `ffprobe`，每次最多均匀抽取 12 个画面。因此它适合判断画面主题、物体、字幕和视觉变化，但不会听取音轨，也不能把抽帧结果当作逐秒完整分析。

媒体没有下载、文件已丢失或环境未安装 `ffmpeg` 时，工具会返回清楚的原因，不会因为需要运行任意命令就直接放开权限。若要安装依赖、提取音频、运行 OCR/转写程序或做更复杂的处理，可新建“工作区 Agent”会话，让 Agent 使用完整命令能力。

## 附件

通过附件按钮、拖放或粘贴图片添加资料。每条消息最多 6 个文件，单个不超过 8 MB，总计不超过 20 MB。上传后可以预览或取消发送；点击发送时才会交给模型服务。

| 类型 | 处理方式与限制 |
| --- | --- |
| PNG、JPEG、WebP、GIF | 最多 2500 万像素；需要支持图片的模型 |
| TXT、Markdown、CSV、JSON、LOG | 支持 UTF-8 和 GB18030 |
| PDF | 未加密、最多 50 页；提取文字，扫描件需以图片上传 |
| DOCX | 提取正文，不读取嵌入图片或复杂版式 |

每个文档最多提取 10 万字，发生截取时会在附件卡片中提示。每个会话最多保存 100 个附件；从输入区移除附件只取消发送，不删除已上传文件。

消息使用本地的 Marked 和 DOMPurify 渲染 Markdown，不执行消息中的 HTML。附件图片直接显示，外部图片需点击后加载。

## 备份

备份数据库，以及运行目录下的：

- `data/web/agent-settings.json`：模型设置，包含密钥。
- `data/web/agent/`：SDK 会话恢复记录。
- `data/web/analysis-attachments/`：附件原文件。

缺少 SDK 恢复记录可能无法接续原会话，缺少附件目录则无法下载历史附件。
